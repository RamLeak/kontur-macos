# План офлайн-снимка вложений, 2026-10-30

## Цель и границы

`download_assets.py` читает только переданный sanitized seed v1 в SQLite
`mode=ro`/`query_only=ON`. Используются фиксированные таблицы
`catalog_metadata`, `catalog_assets` и `catalog_asset_bytes`; SQL из входных
значений не исполняется. Seed не изменяется. Задания, ответы, владельцы,
сессии, ключи и профильные данные не читаются и не копируются.

Для каждой допущенной записи (`source_name=kompege`, права
`private_authorized`/`public_authorized`) строится явный уникальный URL-manifest.
Исходные готовые bytes проверяются и копируются; отсутствующие bytes получают
отдельный снимок в private output. Inline-image locator не превращается в новый
URL: он принимается только при наличии проверенных bytes в seed, иначе остаётся
безопасной ошибкой. Маркеры `upstream_resource_unavailable` сохраняются в
receipt и не подменяются фиктивными файлами.

## Сетевые и файловые ограничения

Единственное разрешённое исходящее обращение — HTTPS к каноническому
`kompege.ru` по `/files/` или `/images/`; credentials, явные порты, фрагменты,
внешние хосты и небезопасные redirect отвергаются. TLS проверяет системный CA,
ambient proxy не используется, cookies/authorization не используются. Перед
каждой попыткой, включая retry и redirect, проверяется DNS и отклоняются
private/link-local/reserved IP. TCP подключается к проверенному числовому IP;
peer сверяется до и после TLS, сертификат проверяется для `kompege.ru`.
Исходный Location проверяется до `urljoin`, включая decoded traversal и controls.

Лимиты: 64,000,000 B на файл после измерения настоящего файла 50,084,031 B,
default 2 GiB всего, максимум 3 worker-а, интервал
между запросами, timeout 15 s, не более одной повторной попытки только для
транзитной ошибки/HTTP 408/429/5xx и не более трёх проверенных redirect.
Общий бюджет резервируется до запроса и ограничивает чтение. При оборванном
запросе резерв учитывается консервативно целиком; retry не обнуляет расход.
Готовые ответы сразу записываются worker-ом, Future хранит только метаданные,
включая неудачные загрузки. Размер и SHA каждой seed BLOB проверяются по одному.
HTML под видом text/plain или octet-stream и оборванный Content-Length запрещены.

Resume требует совпадения `seedSha256` и полного набора `assetIds`; файл повторно
проверяется как regular non-symlink, его ограниченно прочитанные bytes, размер,
тип и SHA сверяются заново. Ожидаемый SHA и MIME всех строк общего URL обязательны.
Запись выполняется атомарно в отдельный output с режимом 0700/0600.

Если один URL имеет несовместимые ожидаемые SHA-256, он остаётся в manifest с
безопасной ошибкой `asset_url_conflict` и не скачивается; подмена одного
варианта другим запрещена.

## Разрешения, запуск и gate

Для реальной сети нужны отдельное разрешение владельца и явный `--allow-network`.
Без флага CLI только проверяет seed/receipt и копирует готовые bytes; DNS и HTTPS
не запускаются. Тестовые seams считаются локальными только при одновременной
подмене transport и resolver. Загрузка learner/private данных запрещена.
Локальная проверка:

```text
resources/python/python.exe -I -B -W error::ResourceWarning -m unittest discover -s ops/catalog-assets-offline-20261030 -p test_*.py -q
```

CLI возвращает `0` для полного снимка, `2` для безопасно неполного снимка,
`1` для ошибки схемы/вывода. Default бюджет остаётся 2 GiB. Явный
`--max-total-bytes` допускает до 8 GiB после отдельной оценки и разрешения
владельца; это combined ceiling для существующих уникальных файлов и новых
сетевых bytes, а не размер выделяемой памяти. Перед возобновлением нужно
сохранить receipt предыдущего запуска и учесть его сетевой расход отдельно.

Точное legacy-условие `expected == content == sha256('metadata:'+url+':'+filename)`,
integer size=0, hash_verified=false, detected_type=null, cache=metadata_only/failed
разрешает снять только служебный expected hash в памяти. Receipt хранит исходный
hash и все поля immutable fingerprint в `legacyHashSentinelNormalization.entries`.
Настоящие ожидаемые SHA не снимаются; финализатор независимо проверяет evidence.

Read-only preflight настоящего v1 подтвердил исходный SHA-256, 3773 admitted rows,
2625 уникальных URL, 109 точных fingerprints и 30 прежних upstream warnings.
Кэш позволил восстановить 290 asset rows (288 URL); 3483 rows (2337 URL) ещё
требуют реальных bytes. Это результат без сети, `exit 2 / INCOMPLETE`.
Снижение относительно прежних 3485 missing rows — повторное использование уже
проверенных bytes общего URL, а не создание файлов.

Исторические upstream warnings сохраняются. Даже после получения всех admitted
bytes snapshot с ними остаётся incomplete; producer v2 отдельно доказывает
`offlineReady=true` без удаления исходных предупреждений.

## Фактический снимок и одобренная замена, 30 октября

Три разрешённых сетевых запуска дали 2624 из 2625 исходных URL; единственный
оставшийся URL `8RgsqOy9c.txt` возвращает HTTP 404. Последний frozen receipt
имеет SHA-256 `49858fb7b447c2a41b3dcb1d91884260245f5ed513f303994131b6e394327dad`.
Ни один настоящий expected SHA не был снят ради получения bytes.

После отдельного решения владельца историческая ссылка task31521/№27 получила
настоящий `Файлы/demo_27.txt` из официального пакета ФИПИ-2027. Его 134074 байта
и SHA-256 `ad36710cf8a489ba6e1d79357974f6e6463b98b5225084be78352ab83407597b`
совпадают с genuine pin текущей ревизии этой же задачи. Историческая побайтовая
идентичность неизвестна: receipt отмечает `official-primary-source-recovery`,
не утверждает успешное скачивание удалённого URL и сохраняет исходный fingerprint.
Все task/revision/link/selection rows и 30 прежних предупреждений сохранены.

Итоговый producer создал v2 с 3773 byte rows, 2586242042 логическими байтами,
`offlineReady=true`, `complete=false`, exit2. Этот exit2 сохраняет исходные
предупреждения; он не разрешает пропуск admitted bytes. Runtime verification
и упаковка учитываются отдельно.
